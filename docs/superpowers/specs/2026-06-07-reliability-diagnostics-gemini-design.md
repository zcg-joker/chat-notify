# Reliability Diagnostics And Gemini Support Design

Date: 2026-06-07

## Product Goal

This iteration improves the Alpha in two ways before the next release:

- Make real-world validation easier by showing a compact monitoring timeline in the popup.
- Add MVP support for the regular Gemini web app at `gemini.google.com`.

This work continues on the current Alpha line. It does not publish `v0.2` yet.

## Scope

Included:

- Add lightweight diagnostics for the most recent monitoring flow.
- Show recent monitoring events in the popup so users can see where a failure happened.
- Keep debug console logs optional and off by default.
- Refactor the page lifecycle bridge so supported sites can define their own generation request detection and prompt extraction.
- Preserve current ChatGPT behavior.
- Add a Gemini adapter for the regular `gemini.google.com` web app.
- Notify only for messages the current user actively sends.
- Support multiple tabs and multiple sessions best-effort, using the same in-memory session model as ChatGPT.

Excluded:

- Do not publish a new GitHub release or Chrome Web Store release in this iteration.
- Do not support Gemini inside non-standard embedded surfaces or enterprise-only variants.
- Do not support sites beyond ChatGPT and Gemini.
- Do not add a long-term activity history.
- Do not store full prompts, assistant responses, request bodies, response bodies, cookies, auth tokens, or conversation URLs.
- Do not add sound, webhooks, or cloud sync.

## Diagnostics Model

The extension should maintain a compact diagnostics object in background storage. It should describe recent operational events without becoming a chat log.

Recommended shape:

```js
{
  latestFlow: {
    flowId: "chatgpt:1780761600000:1",
    siteId: "chatgpt",
    displayName: "ChatGPT",
    promptExcerpt: "short sanitized excerpt",
    updatedAt: 1780761600000,
    events: [
      {
        type: "send_captured",
        status: "ok",
        at: 1780761600000,
        message: ""
      }
    ]
  }
}
```

Allowed diagnostic fields:

- `flowId`
- `siteId`
- `displayName`
- Sanitized `promptExcerpt`
- Event type
- Event status
- Timestamp
- Short error summary

Forbidden diagnostic fields:

- Full prompt text
- Assistant response text
- Request or response body
- Cookies, auth headers, tokens, or account identifiers
- Full conversation URL
- Raw conversation id or raw session key
- Raw stack traces

Only the latest flow needs to be shown in the popup. The implementation may keep a very small bounded recent event list for that flow, with a recommended limit of 8 events.
The `flowId` should be generated by the extension and must not embed raw conversation ids or full session keys.

## Diagnostic Events

Content script and background should report these events:

- `send_captured`: the extension detected a user send action.
- `lifecycle_started`: a generation request started.
- `lifecycle_completed`: the generation stream completed.
- `lifecycle_failed`: the generation request failed.
- `lifecycle_canceled`: the generation was canceled or aborted.
- `notification_sent`: the background created a completion notification.
- `notification_failed`: the background failed to create a notification.
- `notification_focus_succeeded`: clicking a notification focused the source tab.
- `notification_focus_failed`: clicking a notification could not focus the source tab.

Diagnostics are informational. They must not change notification behavior or block normal monitoring.

## Popup Behavior

The popup should keep the existing controls:

- Enabled toggle
- Debug logs toggle
- Test notification button
- Current page support status
- Extension status
- Notification health
- Last completion status
- Privacy note

Add a compact "Recent activity" area that shows:

- Site display name
- Prompt excerpt when available
- Last event status
- A short timeline of recent events

Example copy:

- `Gemini`
- `"Explain Kubernetes..."`
- `Notification sent`
- `Send captured -> Generation started -> Generation completed -> Notification sent`

If there is no recent activity, show `No recent activity`.

The popup should not expose raw stack traces. For failures, show a short single-line reason if available.

## Site Adapter Boundary

Adapters should remain responsible for site-specific behavior:

- Matching page locations.
- Creating a session key.
- Detecting user send events.
- Reading the current prompt draft.
- Reading latest user and assistant message snapshots when needed.
- Reporting whether lifecycle observation is supported.
- Normalizing lifecycle events from the page bridge.
- Providing lifecycle bridge configuration for that site.

The adapter contract should be extended with a bridge configuration method. The method should return serializable metadata only, because it is passed across the isolated content-script/page boundary.

Recommended method:

```js
getLifecycleBridgeConfig()
```

Recommended config shape:

```js
{
  siteId: "gemini",
  hosts: ["gemini.google.com"],
  generationRequestMatchers: [
    {
      pathnameIncludes: "/_/BardChatUi/data/assistant.lamda.BardFrontendService/StreamGenerate"
    }
  ],
  promptExtractor: "gemini"
}
```

The exact Gemini request path may be adjusted during implementation after inspection, but the bridge should remain config-driven.

## Lifecycle Bridge Refactor

The page lifecycle bridge currently has ChatGPT-specific URL and prompt parsing logic. This should become configuration-driven.

Content script flow:

1. Select the adapter for the current page.
2. Inject the lifecycle bridge when the adapter supports lifecycle observation.
3. Send the selected adapter's bridge config to the page bridge.
4. Forward debug log state as it does today.

Bridge flow:

1. Receive and store the active bridge config.
2. Intercept `fetch`.
3. Match generation requests using the active config.
4. Extract a prompt excerpt using the configured extractor.
5. Emit lifecycle events with `siteId`, `lifecycleId`, phase, URL metadata, method, and optional prompt excerpt.

The bridge must continue to monitor a cloned response stream and preserve the original response for the page.

## ChatGPT Compatibility

ChatGPT behavior should remain equivalent to the current implementation:

- Hosts: `chatgpt.com`, `chat.openai.com`
- Conversation session key from `/c/<id>`
- Temporary session key for new chats
- Existing generation paths remain recognized
- Prompt excerpt extraction from ChatGPT JSON request bodies remains supported
- Existing notification behavior and tests continue to pass

## Gemini MVP Behavior

Gemini MVP support targets the regular web app on `gemini.google.com`.

Expected behavior:

- Popup shows Gemini as a supported page on `gemini.google.com`.
- User sends a Gemini prompt.
- The content script captures the send action and prompt excerpt.
- The lifecycle bridge detects the Gemini generation request.
- When the Gemini stream completes, the extension sends a browser/system notification.
- The notification title uses `Gemini`.
- The notification body includes the prompt excerpt when available.
- Clicking the notification focuses the source Gemini tab.

Gemini session key:

- Prefer a stable key from the URL if Gemini exposes a chat/session id in the path.
- Otherwise use a temporary `temp:gemini:*` key for the current tab's in-memory pending response.

Gemini prompt excerpt:

- Prefer the current editor draft at send time.
- If the editor draft is unavailable, extract from the Gemini generation request body when possible.
- Store only the sanitized excerpt.

## Privacy And Safety

Privacy constraints remain central:

- No analytics.
- No external network calls by the extension.
- No full prompt persistence.
- No assistant text persistence.
- No raw request body persistence.
- No raw response body persistence.
- Debug logs remain off by default.
- Diagnostics are bounded, local, and metadata-only.

The diagnostic timeline must not include raw session keys or full conversation URLs.

## Testing Requirements

Automated tests should cover:

- Adapter contract validation includes lifecycle bridge configuration.
- ChatGPT adapter returns a compatible bridge config.
- Gemini adapter matches `gemini.google.com`.
- Gemini adapter rejects unsupported hosts.
- Gemini adapter creates stable or temporary session keys.
- Gemini adapter recognizes send actions.
- Gemini adapter reads prompt drafts.
- The lifecycle bridge matches configured generation requests.
- The lifecycle bridge ignores non-configured requests.
- The lifecycle bridge uses ChatGPT prompt extraction for ChatGPT.
- The lifecycle bridge uses Gemini prompt extraction for Gemini.
- Content script sends bridge config after injection.
- Content script reports diagnostic events for send capture and lifecycle phases.
- Background records notification success and failure diagnostics.
- Background records notification focus success and failure diagnostics.
- Popup renders no recent activity state.
- Popup renders a recent activity timeline.
- Existing ChatGPT tests continue to pass.

Manual validation should cover:

- ChatGPT still sends notifications with correct prompt excerpts.
- ChatGPT notification click still focuses the source tab.
- Popup recent activity updates through a ChatGPT completion flow.
- Gemini regular web app is reported as supported.
- Gemini prompt completion sends a notification with the prompt excerpt.
- Gemini notification click focuses the source tab.
- Popup recent activity updates through a Gemini completion flow.
- Failure states are understandable when notifications permission is disabled.
